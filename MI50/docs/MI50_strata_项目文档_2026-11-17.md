# Strata 在 MI50（gfx906）上的移植、调优与性能基线

**平台**：2 × Radeon Instinct MI50 32 GB（gfx906）· AMD EPYC 7F52 · 247 GB RAM · 主机 `amd52`（10.24.247.157）
**软件**：Strata v0.2.14.1（engine `0.1.60.1`，commit `3af562d5`）· ROCm 7.15（gfx906 定制 `/opt/rocm715-gfx906`）· rocBLAS `5.6.0.baa93758`
**模型**：`strata-pack-ud31-q4kxl`（Qwen3.8-Flash-Next，UD-Q4_K_XL：43 层 `12/7`、4 层 `12/8`、1 层 `13/8`）+ MTP 草稿层
**日期**：2026-11-16 ~ 2026-11-17
**范围**：本文只覆盖 MI50/gfx906 这条线。同机的另一张非 MI50 显卡只作为"必须隔离的设备"出现在启动参数里。

## 0. 结论摘要

| 指标（21 000 token 请求，双卡层切） | v0.2.10 基线 | **当前版本** | 变化 |
|---|---:|---:|---:|
| 21K prefill | 651.5 tok/s | **941.8 tok/s** | **+44.6%** |
| 21K TTFT | 27.386 s | **18.33 s** | **−33.1%** |
| 5K prefill | 415.9 tok/s | **645.9 tok/s** | +55.3% |
| 5K TTFT | 11.084 s | **7.09 s** | −36.0% |
| 40K prefill | — | **942.9 tok/s** | — |
| 21K decode | 64.4 tok/s | ~64.7 tok/s | 持平（刻意不动） |

分层归因（相对 0.2.14.1 默认参数）：

| 手段 | 收益 | 性质 |
|---|---:|---|
| `--prefill 2048` + `--mtp-q4 all` | 5K prefill +24.7%、TTFT −19.8%、21K decode +6.4% | 配置 |
| `STRATA_HIP_PROMPT_F16=1` | prefill +15~17% | 环境变量（改变 GEMM 输出精度通路） |
| gfx906 放开 rocBLAS 选解表 + 表按真实 T 桶重校准 | +1.6%（同日 A/B 926.7 → 941.8） | cmake 守卫 + 纯文本表 |
| i8 专家内核 2 blocks/CU（单缓冲 LDS + 强制 128 VGPR） | 整机 +9.2%，单算子 −32% | 内核 |
| `--prefill 3072` | 21K/40K 最优（5K 比 2048 低约 5%） | 配置 |

**没有做到的**：方案 4（三级预取 PF=2）只值 ±1%，在噪声带内；方案 2（strata-pack 权重重排）逐位正确但慢 0.3~1.4%，已实现但不启用；"i8 有效带宽 41 GB/s 是随机 128 B 小读造成"这一归因被硬件计数器推翻（请求本来就是整条 128 B 线）。距 950 tok/s 还差 0.9%，剩下的账见 §8。

> 口径说明：**941.8** 是与旧 rocBLAS 表同日 A/B 的中位，作为正式基线引用；**946.3** 是收官夜"零 i8 环境变量"验证的中位，两者相差 0.5%，属不同时段的机器状态差，不要互减。

## 2. 依赖与编译

### 2.1 依赖清单

- ROCm 7.15 gfx906 定制版（含 `hipcc`/`clang++`、rocBLAS、hipBLAS、hipblasLt、rocprofv3 1.3.5）
- CMake ≥ 3.24 + Ninja
- Python 3（`venv-strata`，serve.server 依赖）
- 模型与 PLE 表（`strata-pack-ud31-q4kxl`，含 `native_experts.txt`、`tokenizer`）
- 磁盘：源码 + build ≈ 3 GB；模型 pack ≈ 数十 GB；`/data` 需留出 expert-cache 空间

### 2.2 编译前置补丁（唯一必需）

0.2.14.1 的 HIP 兼容层缺两个流优先级宏，`src/core/dflash2.cpp` 会报 undeclared identifier。补丁 2 行，已包含在本次改动里（`include/strata/platform/hip_compat/strata_hip.h`）：

```c
#define cudaStreamCreateWithPriority hipStreamCreateWithPriority
#define cudaDeviceGetStreamPriorityRange hipDeviceGetStreamPriorityRange
```

除此之外 gfx906 零改动编译通过。

### 2.3 编译命令

```bash
ssh -p 2222 yanyq@10.24.247.157
cd ~/port
bash build_mi50_0214.sh          # 约 2 分钟（24 并发，增量更快）
# 可选：MMQ=1 bash build_mi50_0214.sh   —— 906 上 MMQ 不可用（见 §10.1）
```

脚本等价的手工命令（关键点）：

```bash
cmake -G Ninja -S ~/port/mi50-0214 -B ~/port/mi50-0214/build-906-0214 \
  -DCMAKE_BUILD_TYPE=Release \
  -DSTRATA_ENABLE_HIP=OFF -DSTRATA_ENABLE_CUDA=OFF -DSTRATA_BUILD_TESTS=OFF \
  -DSTRATA_HIP_GFX906=ON \
  -DSTRATA_MMQ=OFF -DSTRATA_PREFILL_MMQ=OFF \
  -DCMAKE_HIP_ARCHITECTURES=gfx906 \
  -DCMAKE_C_COMPILER=/opt/rocm715-gfx906/llvm/bin/clang \
  -DCMAKE_CXX_COMPILER=/opt/rocm715-gfx906/llvm/bin/clang++ \
  -DCMAKE_HIP_COMPILER=/opt/rocm715-gfx906/llvm/bin/clang++ \
  -DCMAKE_HIP_COMPILER_ROCM_ROOT=/opt/rocm715-gfx906 \
  -DCMAKE_PREFIX_PATH=/opt/rocm715-gfx906 \
  -DCMAKE_HIP_FLAGS="--rocm-path=/opt/rocm715-gfx906 --rocm-device-lib-path=/opt/rocm715-gfx906/lib/llvm/amdgcn/bitcode"
ninja -C ~/port/mi50-0214/build-906-0214 strata -j 24
```

环境变量（编译期）：`HIP_PLATFORM=amd HIP_COMPILER=clang HIP_RUNTIME=rocclr ROCM_PATH=/opt/rocm715-gfx906 PATH=/opt/rocm715-gfx906/bin:$PATH`。

### 2.4 可调编译宏（源码级，默认值已按 gfx906 固化）

| 宏 | 默认（本次） | 含义 |
|---|---|---|
| `I8_SMEM_1BUF` | **1** | stage 记录/激活单缓冲：LDS TM2 = 20 496 B，支撑 2 blocks/CU；代价是每 stage 两次 `__syncthreads()` |
| `I8_MINB` | **2** | `__launch_bounds__(256, 2)`，强制每 CU 两个 block，把 VGPR 卡在 ≤128 |
| `I8_ST_UNROLL` | **2** | 展开 128 值 stage 循环，使预取环下标成为编译期常量（否则 PF 反变慢 16%） |
| `I8_BLK_UNROLL` | 1 | 32 值子块循环展开，保持上游默认 |

| `--prefill` | `3072` | prefill 分块，21K/40K 最优；5K 比 2048 低约 5% |

| `--ple-gguf` | `...-00004-of-00004.gguf` | PLE 表来源分片 |

| 变量 | 生产值 | 作用 | 依据 / 验证 |
|---|---|---|---|

| `STRATA_I8_COUNT` | `1`（诊断） | 每 chunk 打印 i8 覆盖统计 | 验证 100% 走 native_expert_i8 |

| `STRATA_ROCBLAS_VERBOSE` | `1`（诊断） | 打印每个形状的命中解 | 验证表加载与 T 桶 |

## 5. 变更记录（逐项）

### 5.1 第 1 轮：v0.2.14.1 移植（2026-11-16）

| # | 位置 | 改动 | 依据 / 原因 | 影响范围 | 验证 |
|---|---|---|---|---|---|
| 1.1 | `include/strata/platform/hip_compat/strata_hip.h` | +2 行流优先级宏 | gfx906 兼容头缺 `cudaStreamCreateWithPriority` / `cudaDeviceGetStreamPriorityRange`，`dflash2.cpp` 编译失败（与 0.2.10 同一个坑） | 仅 HIP 兼容层 | 编译通过，二进制可跑 |
| 1.2 | `cfg-mi50-*.json` | `--prefill 4096 → 2048`（后改 3072） | 5K prefill 比 4096 快 18%，21K 持平：帕累托改进 | prefill 切块 | 5K 438.6→518.5 t/s |
| 1.3 | 同上 | `--mtp-q4 all` | 草稿层 4bit 化，KV/激活带宽下降 | decode | 21K decode 65.4→68.5 t/s |
| 1.4 | 同上 | `--kv-resident 262144 → 32768` | 全量常驻挤占专家缓存；32K 常驻命中率足够 | 显存/KV | 5K 523.0 t/s、21K 667.6 t/s（+1.0~1.2%） |
| 1.5 | 启动器 | `taskset -c 0-15` | 独占 16 物理核，避免 SMT 抖动 | host 侧 | 实测收益 0（保留为稳态措施） |

### 5.2 第 2 轮：三项优化（2026-11-17 上午）

| # | 位置 | 改动 | 依据 / 原因 | 影响范围 | 验证 |
|---|---|---|---|---|---|
| 2.1 | 启动器 | `STRATA_HIP_PROMPT_F16=1` | `gemm.cu:605 prompt_f16()` 的 `f16_io` 默认只对 gfx1103 开；906 输出 FP32，多一倍写出带宽 | prompt dense GEMM 输出精度 | 5K 518.5→602.8、21K 660.6→778.3（+15~17%）；eval100 27/28 逐题一致 |
| 2.2 | `cmake/backends/hip.cmake` | +9 行：`find_package(rocblas CONFIG QUIET)` → `STRATA_ROCBLAS_AVAILABLE` | gfx906 走 CUDA 兼容分支，`cmake/hip_backend.cmake` 的探测从不执行，`gemm.cu` 的 `RocBlasState`/`try_rocblas_f16o` 整段被编译掉 | 构建配置 | `build.ninja` 出现 `STRATA_ROCBLAS_AVAILABLE=1`；`ldd strata` 见 `librocblas.so.5` |

### 5.3 第 3 轮：i8 专家内核 —— 三级预取、packed 重排、tile 扫描（2026-11-17 下午）

| # | 位置 | 改动 | 依据 / 原因 | 影响范围 | 验证 |
|---|---|---|---|---|---|

| 配置 | 21K pp（各 rep） | 说明 |
|---|---:|---|
| **一个 i8 环境变量都不设**（仅 PROMPT_F16 / ROCR / taskset） | **946.3**（935.8 / 957.0 / 946.3） | 源码 `TM=2`、`PF=1` 默认生效；这是"重启/升级后什么都不配"的真实水平 |

改成 2，两个默认一起才能保证"零配置 = 黄金档"。

## 10. 关键注意事项（踩过的坑）

1. **`STRATA_HIP_GFX906` 与 `STRATA_ENABLE_HIP` 互斥**；`STRATA_PREFILL_MMQ` 依赖后者，所以 906 无 MMQ prefill。
2. **906 兼容头缺两个宏**（流优先级），编译前必须补，否则 `dflash2.cpp` 报 undeclared identifier。
3. **卡序**：`0 = MI50`、`1 = 另一张卡`、`2 = MI50`。`--gpu 0,1` 必须配 `ROCR_VISIBLE_DEVICES=0,2`，否则会把权重分到错误的卡上。
4. **PF=2 + TM=3 = 690 tok/s**（spill 最重）；**PF=2 + TM=2 = 863.9**（−8.7%）；**TM=4 + MINB=2 = 783**（spill 27）。三个默认值都已在源码按 gfx906 固化（`TM=2`、`PF=1`，§5.6），但显式传错环境变量仍会踩。
5. **`i8_pack_bench` 的 entries 必须 ≥1536**：小于 1536 会退化成 1 个 group，而镜像按 16 blob 建，指针数组越界 → `HSA_STATUS_ERROR_MEMORY_APERTURE_VIOLATION`。
6. **`pkill -f "serve.server"` 会杀掉自己**：改用 `ps -eo pid=,comm=,args= | awk '$2=="python" && /serve.server/ {print $1}'`。
7. **rocprofv3 的绝对耗时不可引用**：serial 化放大 ~11×，并触发引擎 native verify watchdog（5 s）让请求 503。只看占比结构。
8. **`run_trace21k.sh` 的 `rm -rf $OUT` 会删掉上一轮 CSV**：脚本已改为拒绝复用目录。
9. **`tune_i8.sh` 的 `grep "1[0-9]* tokens" | tail -1` 取的是尾块（1360 tokens）**，不是整段 21K。整段请用 `167xx tokens` 那行。
10. **rocBLAS 表 T 桶**：`closest()` 要求 N/K/ldy 精确相等，仅 T 最近邻。新增形状必须把所有 T 桶补齐，否则落回 `MT16x16x24` 默认内核。
11. **rocBLAS 解可能被拒**（status 6，连拒 3 次后整形状永久回默认）。校准时必须逐个验证输出（`relative_l2 ≈ 2e-5`、`padding_writes=0`）。
12. **eval100 非确定**：同一构建连跑 4 次，MMLU 有 58.8/52.9 两档。任何"单次涨跌"都不能当结论。
13. **8013 端口残留**：起测试服前必须确认 `ss -ltn | grep 8013` 为空，否则新进程会绑定失败而脚本仍显示 started。
14. **`--gpu` 会改写 `HIP_VISIBLE_DEVICES`**：两类可见性变量要配对设置。
15. **PLE 表在 IQ3_XXS / IQ4_XS / Q4_K_XL 之间是同一 inode**：两套服务物理共享一份 26.8 GiB，不要重复拷贝。

### 11.3 推送到 GitHub 的两个坑（已处理）

`~/port/mi50-0214` 是 `git clone --shared` 的 shallow checkout（上游 `~/strata` 本身 shallow），直接 `git push` 会报
`remote: fatal: did not receive expected object … / index-pack failed`，原因是对象只存在于 alternates 且历史残缺。
处理方式：

```bash
# 1) 从上游补全历史（读公共仓库，yanyuqin 的 key 有读权限）
cd ~/port/mi50-push        # 由 git clone --dissociate 得到的独立对象库
git fetch --unshallow git@github-port:Niko1221/Strata.git '+refs/heads/*:refs/remotes/upstream/*'
# 2) 工作树提交后同步进来再推
git fetch ~/port/mi50-0214 mi50-0214 && git merge --ff-only FETCH_HEAD
git push gfx906 HEAD:main
```

`~/port/mi50-0214` 仍是编译工作树；`~/port/mi50-push`（114 MB .git，无 alternates）是推送仓库。**不要**在
`mi50-0214` 里手动删 `alternates` —— 历史不全，会直接损坏对象库。
