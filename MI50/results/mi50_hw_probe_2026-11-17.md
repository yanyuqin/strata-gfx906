# MI50 (gfx906) 硬件实测：带宽 vs 算力（2026-11-17 06:xx，amd52）

回答"660 t/s 的 prefill 天花板是不是 HBM 带宽"——不是。MI50 是 HBM2 1024 GB/s，实测也没到顶。

## 硬件

- 2× Radeon Instinct MI50 32 GB，gfx906，Max Clock 1800 MHz，L2 8 MB，wave64
- 标称：HBM2 1024 GB/s，FP16 26.5 TFLOPS（**fp16 累加**），FP32 13.3 TFLOPS

## 实测（`/home/yanyq/bench/probe/`）

### 带宽（mem_bw.cpp，512 MiB DtoD，读+写）

| rep | GB/s |
|---|---|
| 1-5 | 610 / 803.8 / 800.7 / 811.1 / 803.8 |
| 峰值 | **811.1 GB/s** = 标称的 79% |

### FP16 GEMM（gemm_eff.cpp，hipblasGemmEx，fp32 累加）

| 形状 | ms/launch | TFLOPS |
|---|---|---|
| M=40 N=640 K=2560 | 0.072 | **1.8** |
| M=80 N=640 K=2560 | 0.088 | **3.0** |
| M=160 N=640 K=2560 | 0.102 | 5.1 |
| M=320 N=640 K=2560 | 0.186 | 5.6 |
| M=640 N=640 K=2560 | 0.279 | 7.5 |
| M=2048 N=640 K=2560 | 0.708 | 9.5 |
| M=2048 N=4096 K=4096 | 6.380 | 10.8 |
| M=4096 N=4096 K=4096 | 12.669 | **10.8（单卡上限）** |

关键：标称 26.5 TFLOPS 是 **fp16 累加**；推理必须 fp32 累加，天花板是 FP32 的 13.3 TFLOPS，实测 10.8（81%）。

## 模型侧（gguf metadata + 全分片张量统计）

- `qwen4exp`：48 层、512 experts/layer、expert_used 10、expert_ff 640、n_embd 2560、head 24/2
- 总参 **176.94 G**（moe 120.80 + emb_head 52.48 + attn 2.42 + dense_ffn 0.55 + router 0.06 + other 0.63）
- 每 token 激活 **4.85 G**（2×4.85 = 9.7 GFLOP/token）

## 对上实测吞吐

| 档 | t/s | TFLOPS 需求 | 对应 |
|---|---|---|---|
| 21K prefill | 662.6 | 6.4（双卡） | 双卡 M=40~80 区间（3.6~6.0） |
| 5K prefill | 518.5 | 5.0（双卡） | 双卡 M≈160（~5.1） |
| 21K decode | 68 | 0.66 | 每 token 读 ~2.85 GB active → ~194 GB/s，HBM 的 24% |

带宽占用：21K prefill 27 s 读 54.36 GB 专家 → **2.0 GB/s**，HBM 的 **0.25%**。

## 结论

瓶颈 = **MoE 稀疏专家 GEMM 行数太少（M≈40~160）** × gfx906 无 MFMA + fp32 累加 10.8 TFLOPS/卡。
不是 HBM 带宽（811 GB/s 实测，占用 0.25%），不是显存容量（32 GB 影响的是 cache 槽位，不是单请求速度）。
